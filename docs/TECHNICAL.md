# 1.0.12.72 适配原理与兼容配置

本分支基于 [上游 v1.1.0](https://github.com/yeeesy/Civ6-2K-Online-Fix/tree/v1.1.0)（`6945bc1`），沿用原作者的同步故障保护方案。本文记录新增适配的依据，实际观察见 [VALIDATION.md](VALIDATION.md)。本文中的地址均为公开配置需要的 **RVA（相对映像基址的偏移）**，不是某次运行的个人内存地址。

## 从现象到诊断

本次在 Windows Steam 游戏 `1.0.12.72 (1327737)`、Steam build ID `26407122` 上复现：Steam 和常规网络可用，但游戏的 2K/互联网功能离线。换热点、重新登录 Steam、补注册并绑定 2K 没有使本次故障消失；这些尝试并不能证明所有网络或账号问题都已排除。

未装保护的一次启动中，观察到：

- OpenSSL 使用的锁向量第 18 项互斥锁计数为 `-1`；
- Discovery 和 SSO 状态为 `3/3`，未到代码采用的就绪值 `4/4`；
- FiraxisLive 登录失败，出现 `514 (ERROR_NOT_INITIALIZED)`。

这些观察结合上游修复机制，支持“特定解锁使初始化流程受阻”的诊断；`514` 本身不是唯一根因证明，也不能从状态 `3` 推导出某个数据库或网络阶段。不要据此删除 SQLite、存档或账号文件。

## 保护器做什么

1. 确认 Steam 安装位置和实际游戏进程，匹配 EXE 名、完整 SHA-256、文件大小、PE 身份及映像映射。
2. 核对进程 PID、创建时间、路径和运行时身份，防止将已退出进程或同名替代进程当作目标。
3. 核对系统 `System32\MSVCP140.dll` 的 `_Mtx_unlock` 导出与游戏 IAT 当前值；未知运行库、已有其他钩子或无法确定所有权时停止。
4. 在允许写入的精确配置上，于游戏中分配 `0x2000` 字节作为保护代码/计数存储，安装 51 字节 Guard，并将 `_Mtx_unlock` IAT 指针指向它。
5. Guard 检查调用返回位置，只有来自配置内 OpenSSL 回调的解锁、且互斥锁计数 `<= 0` 时，跳过本次无效调用并计数；其他解锁仍交给原函数。
6. 读取拦截计数和 Discovery/SSO；记录就绪、超时、读取失败或取消。工具不代替游戏进行网络请求或认证。

需要在游戏初始化发生异常前介入，因此推荐先监听再启动游戏。工具不承诺将已经出错的 `-1` 状态原地恢复；失败后应退出游戏再重新开始。

## 新配置的额外校验

旧版配置保持上游行为。新增配置设置 `verifyUnlockCallback=true`，在 `Win32FixPlatform::ValidateRuntime` 读取回调并调用 `MatchesUnlockCallback`：

- 回调起点是 `opensslUnlockReturnRva - 37`，读取 59 字节。
- 除四处 32 位 RIP 相对位移外，每个指令字节必须和内置结构相同；不进行模糊搜索。
- 位移按有符号 32 位解码，计算 `callbackRva + operandOffset + 4 + displacement`。
- 计算结果必须逐项等于配置中期望的目标，不能仅凭指令形似认定兼容。

| 位移在回调内的偏移 | 预期目标 RVA | 意义 |
| --- | --- | --- |
| `7` | `opensslLockVectorRva` | OpenSSL 锁向量 |
| `25` | `mtxUnlockIatRva + 8` | `_Mtx_lock` IAT |
| `33` | `mtxUnlockIatRva` | `_Mtx_unlock` IAT |
| `50` | `mtxUnlockIatRva - 0x30` | 异常处理跳转 IAT |

任何读取失败、指令变化或目标不符都会以运行时不匹配结束，不安装 Guard。该附加检查没有取代文件身份、模块、运行库或写入前重验。`ReadOnlyCandidate` 即使通过检查也不会获得写句柄或调用安装流程。

## 生命周期与失败处理

Guard 安装、IAT 指针发布和页面保护变更分别检查结果并回读；写入前再次确认目标仍然一致。取消时只尝试恢复本会话仍拥有的 IAT 指针，不覆盖第三方改动，页面保护恢复结果独立报告。

成功或监控超时后，Guard 可保留到本次游戏退出。即便取消后指针已恢复，也不在游戏仍可能执行旧入口时释放远程内存，避免返回到已释放代码。游戏退出后由操作系统回收。关闭工具不等于“热卸载”。

此设计不修改磁盘上的游戏 EXE、系统 DLL、存档或账号数据，不安装服务、驱动或系统启动项。运行库版本、时序、并发和第三方组件仍影响能否安全安装；必要条件不满足就失败关闭，而不是降低检查。

## Steam 自动启动器

`launcher/Civ6-Start.cs` 只有一个入口文件：

1. 接收 Steam 展开 `%command%` 后传入的游戏路径与参数，只接受两个已知游戏文件名。
2. 以隐藏窗口、非 shell 方式运行同目录修复器：`--no-gui --watch-only`。
3. 从标准输出等待 JSON `listener_ready`，兼容上游中文监听提示；最长等待 60 秒。
4. 游戏参数逐项使用 Windows 引号规则重新编码，保留空参数、引号、尾随反斜杠及 Unicode。不会把参数拼进 PowerShell/cmd 脚本。
5. 运行 Steam 原游戏命令并等待退出，返回其退出码。修复器不可用时写本机日志并回退到启动游戏。

启动器不会选择 DX11/DX12、修改 Steam 配置或保证回退后的在线状态。新增 `listener_ready` / `session_completed` 事件让自动化能识别就绪和终态；这些原始事件仍属于本机日志，不作为公开诊断输出直接上传。

## 如何适配下一次更新

先收集官方版本、渠道、文件名、大小和 SHA-256，以只读候选建立配置。在合法本地副本中独立核对 PE、回调结构、所有相对引用、运行库导出及状态对象关系，不能按“新版大概偏移了多少”推算。

随后在冷启动中做只读运行验证，确认没有写句柄和进程写入；对未知哈希、渲染器错配、字节变化、错误相对目标、读取失败和身份变化运行负向测试。候选只通过静态分析时继续保持只读。允许写入前必须检查运行时目标和正向结果；实测范围、机器数量及未覆盖条件应公开记录，不能把一次成功包装成普遍保证。

请只提交源码、配置和脱敏记录，不上传游戏文件、内存转储、原始日志或账号信息。维护和发布步骤见 [MAINTAINER.md](MAINTAINER.md)。
