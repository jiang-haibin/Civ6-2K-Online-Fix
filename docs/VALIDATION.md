## 自动化验证

- 核心测试保留上游的身份、IAT 所有权、恢复、取消、超时、读取失败及脱敏诊断测试。
- 新增精确新版 Profile 契约、DX11 只读/DX12 可写分流、文件名与渲染器哈希错配测试。
- 新增回调指令变化、锁向量以及三处 IAT 相对目标变化的拒绝测试。
- 启动器测试使用临时编译的无害占位程序，不启动实际游戏：两个游戏文件名各覆盖修复器缺失、提前退出、正常就绪；检查等待次序、原生退出码及复杂参数往返。
- 校验器测试拒绝多余文件、重复哈希条目和目录逃逸；发布策略测试约束依赖固定提交、只读权限、日志/密钥排除及压缩包外部校验文件。
- MinGW 开发构建运行同一组回归，但不声称执行 MSVC `/analyze`、CFG/CET 或确定性发布检查。
- Windows CI 必须通过 MSVC `/W4 /WX`、`/analyze`、离线自检、严格打包、文件集合/哈希核验，再从包内源码异路径重建，逐字节比较修复器和启动器。

每次运行的断言数量、编译器能力和程序哈希在生成的 `build_manifest.json` 中记录；实际 CI 结果以 [Actions](https://github.com/jiang-haibin/Civ6-2K-Online-Fix/actions) 对应提交为准。不要把静态配置测试当作真实进程或网络集成测试。
